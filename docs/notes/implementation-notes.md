# 实现说明

## 1. 宿主兼容性

接口基线是 DSH npm `0.2.2-rc.1`。同版本的 npm 与桌面随包构建有插件行差异，
例如 npm 构建缺少 `ui-agent-team`，普通 preset 检查会告警；升级核对可使用 `--strict`。
生成器提供显式上游目录参数，也能从 DSH 安装位置发现上游包。

## 2. 实现取舍

- 身份 section 由启动器运行期注册且关闭插值，避免 patch 求值时读取尚未注入的服务。
- `--once` 不启用调度，避免一次性进程成为第二个定时投递者。
- 工具状态来自持久会话事件；终稿按回合结算，崩溃后不重放副作用。
- 入站附件延后到白名单检查之后准备；收据和请求 id 保持各自的幂等职责。
- 权限继承底座默认值。聊天审批使用独立的内存待办，避免与普通问题的超时补答语义混用。
- 不在安装器中隐式安装额外 MCP 管理插件，扩展由部署者独立选择。

## 3. 自动化验证

`pnpm verify` 包含 JSDoc 类型检查、Node.js 业务回归、preset 快照与禁用名单核对。
假宿主按 [DSH 接口契约](dsh-api-contract.md) 提供事件和服务，审批测试只覆盖普通请求的生命周期，
不执行需要扩大权限的真实文件或命令操作。安全修复采用静态复核。

## 4. 已知限制与待验证项

| 项目 | 当前范围或所需验证 |
|---|---|
| 真实 Telegram 附件、菜单、typing、话题与分条呈现 | 公开版本需要客户端业务验收 |
| 聊天审批 | 普通生命周期回归；真实 DSH 工具请求与 Telegram 按钮交互需要环境验收 |
| DSH 沙箱 | 依赖宿主执行后端及系统支持，工作区写入模式不隔离整机读权限或网络 |
| 既有会话 | 会话保留原权限策略，新默认值不自动修改既有记录 |
| 定时任务聊天目标 | 已绑定的 session 可投递；new/new_once 不自动建立聊天绑定，无路由输出只留未投递记录 |
| 无路由审批及 --once | 无可用应答方时拒绝，不将请求转发给其他聊天 |
| 真实 429 与断连恢复 | 常规错误语义有单测，线上限速和恢复需业务环境验证 |
| 多 owner、多话题并发 | 需要相应真实使用场景验收 |
| /compact、/goal、模型切换 | 转发有普通回归，真实模型效果需要会话验证 |
| 开机自启、完整恢复 | 需部署环境验收 |
| 第三方 MCP | 默认未安装管理器或 server，需另行配置和验收 |
| 配置变更 | 身份和话题设置在启动时加载，修改后重启生效 |

## 5. 维护

DSH 升级后重新核对接口契约、生成 preset 并查看差异，再运行 `pnpm verify`。
部署路径由环境和安装器计算，凭据与运行状态不进入公开仓库。
